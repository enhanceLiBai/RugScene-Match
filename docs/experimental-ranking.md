# 实验排序分：DeepSeek Top10

当前流程：客户场景识别 → 场景硬筛 → 向量相似度最高的10个商品代表图 → DeepSeek排序属性判断 → 配置加扣分排序 → 返回所需条数（最多10条）。已取消冲突复审，硬筛排除的图片不再考虑。原有按商品选最高向量分代表图的逻辑保留。

每次最多一次批量模型调用，第一张为客户照片，随后最多10张候选，提示词包含图片ID对应关系。DeepSeek判断候选自身的拍摄距离、地毯可见面积，以及客户与候选的整体冷暖氛围关系。模型不输出总分，也不重新判断准入。

|指标|档位|分值|
|---|---|---|
|拍摄距离|正常 / 远景 / 极远景 / 无法判断|0 / -4 / -8 / 0|
|地毯占比|至少15% / 5%至不足15% / 不足5% / 无法判断|0 / -4 / -8 / 0|
|整体冷暖关系|相同 / 相近 / 不同 / 无法判断|+4 / +2 / 0 / 0|

整体色调已取消RGB统计。两张照片的整体冷暖氛围由DeepSeek比较，包含偏暖、偏冷、中性、混合光线；相同装修主色不等于同冷暖。色调关系每次重新判断，不按买家秀ID复用。

最终排序分=原始向量相似度+上述调整，可超过100，不是概率。分值、候选数量及等待预算集中于 backend/ranking.py。响应保留 similarity，增加 ranking_score、ranking_reasons；客户结果与历史快照均显示。

构图按图片ID缓存于 data/ranking-labels/<ID>.json，含模型与版本。已有构图复用，新增只保存构图，不保存本次色调关系。每进程最多2个批次同时调用，繁忙不继续排队；每个请求额外等待最多30秒，模型网络超时25秒。模型超时或繁忙时，只使用已缓存构图扣分，未完成构图暂不扣分、色调不加分，并显示未完成提示。后台批次若随后完成可保存构图供后续使用，不回写已返回的历史分数。首次补标与后续排序可能不同。

验证：模型模拟测试覆盖Top10限制、缓存复用、每次重新比较色调、未知值零调整、额外ID排除及等待上限；接口测试验证分数字段与硬筛拒绝候选不复审。本次没有调用真实付费模型做11图响应耗时验证。


## 冷暖判断修正（2026-09-17）

使用用户提供的两张图片、另选9张图库图做一次2×2真实模型对照（并非原故障批次的精确复现）：旧提示词双图 close（1.59秒）、旧提示词11图 same（4.94秒）、新提示词双图 different（1.59秒）、新提示词11图仍 close（5.25秒）。新提示词两次均分别识别客户 cool_neutral、候选 warm_neutral；批量时关系结论与档位矛盾。这支持提示词定义和批量一致性均需改善，单次对照不能断言模型普遍准确率。

现在要求DeepSeek逐图输出 query_tone、candidate_tone 以及两图各自可见依据。优先评估室内墙、天花、裸露地面的实际光色，不消除暖光，不以木墙黄椅等固有物体色判断照明，也不把明亮等同偏暖。

冷暖档位序列：偏冷、中性偏冷、中性、中性偏暖、偏暖。代码按模型给的档位比较：相同+4、相邻+2、相隔至少两档+0。冷暖混合、无法判断、缺失档位或依据都不加分。模型仍负责视觉判断，代码只执行确定的分值关系，不采纳其可能矛盾的 same/close 总结。结果理由展示客户与买家秀的各自档位和依据。构图缓存不变；新规则不会重算旧历史快照。
