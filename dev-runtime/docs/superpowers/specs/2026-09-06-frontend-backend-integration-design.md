# 前后端图库与图片检索集成设计

> 日期：2026-09-06  
> 状态：已在 `codex/frontend-backend-integration` 分支实施，当前等待合并
> 执行说明：本文是已实施功能的设计基线，不构成新的实现、测试或审查任务。
> 范围：将现有静态前端的图库录入、图库查看和相似图片检索统一接入 FastAPI 后端

## 1. 目标

客服通过同一个 Web 页面完成以下流程：

1. 上传买家秀图片，并可选择填写商品元数据；
2. 从后端数据库查看所有已入库买家秀；
3. 上传客户家居图，通过 OpenCLIP 和 pgvector 检索相似买家秀；
4. 在检索结果中查看已确认的商品信息和建议话术。

完成后，浏览器 IndexedDB、九宫格色调特征和演示图库不再作为业务数据源。图片、向量和选填元数据均以后端为准。

## 2. 范围边界

本次实现包含：

- FastAPI 同源托管 `index.html`、CSS 和 JavaScript；
- 买家秀图片及选填元数据的 HTTP 入库接口；
- 图库列表和检索结果返回选填元数据；
- 前端通过 HTTP 完成入库、列表刷新和检索；
- 对已有数据库执行幂等的增量 schema 升级；
- 自动化测试和同源页面验证。

本次不包含：

- 用户、权限或多租户；
- 单条编辑、单条删除或批量清空图库；
- 商品库存系统同步；
- AI 自动生成商品元数据；
- 将多个 SKU 或多个规格建模为独立关系；
- 前端构建工具或 JavaScript 包管理器。

## 3. 运行方式与同源边界

`python -m backend.cli serve` 启动 FastAPI 后，应用在同一地址提供页面和 API。默认入口为：

```text
http://127.0.0.1:8000/
```

页面使用相对 URL 调用 `/api/...`，图库图片也使用后端返回的相对 `image_url`。不增加 CORS 配置，不再支持把 `index.html` 作为正式使用方式直接双击打开。

后端只显式暴露以下静态文件：

- `/` → `index.html`
- `/styles.css` → `styles.css`
- `/matcher-core.js` → `matcher-core.js`
- `/api-client.js` → `api-client.js`
- `/app.js` → `app.js`

静态文件路径由服务端固定注册，不能通过用户输入读取任意项目文件。

## 4. 数据模型

在现有 `images` 表上增加以下可空列：

| 字段 | PostgreSQL 类型 | 含义 |
|---|---|---|
| `sku` | `text` | 地毯 SKU |
| `product_name` | `text` | 商品名称 |
| `size` | `text` | 主推规格 |
| `price` | `numeric(12, 2)` | 非负参考价 |
| `room` | `text` | 空间 |
| `style` | `text` | 风格 |
| `color` | `text` | 主色描述 |
| `stock` | `text` | 库存展示文本 |
| `selling_point` | `text` | 成交亮点或话术依据 |

所有字段均为选填。空字符串在 API 边界统一转换为 `NULL`；`price` 仅接受大于等于零且最多两位小数的值。

`create_database_and_schema()` 在 `create_all()` 后执行幂等 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，使已有开发数据库无需删除数据即可升级。ORM 模型同步声明这些列。

本阶段直接把元数据放在 `images` 表中，因为每张买家秀当前只关联一组展示信息。未来需要一图多 SKU 或接入商品主数据时，再迁移为独立关联表。

## 5. 后端接口

### 5.1 `POST /api/library`

请求使用 `multipart/form-data`：

- `image`：必填图片，支持 JPG、JPEG、PNG、WEBP，最大 20 MiB；
- `sku`、`product_name`、`size`、`price`、`room`、`style`、`color`、`stock`、`selling_point`：选填文本字段。

处理顺序：

1. 在内存中读取并校验上传大小与图片内容；
2. 计算 SHA-256，查询是否已有相同原始文件；
3. 新图片安全写入 `data/images`，创建图片记录；
4. 已有图片使用本次提交的非空字段补充或覆盖对应元数据，未提交和空白字段不清除既有值；
5. 若当前模型向量缺失，则生成并写入向量；
6. 在服务层提交数据库事务；如果新文件对应的事务失败，仅清理本次新建文件；
7. 返回最终图片记录和入库状态。

状态值沿用应用层语义：

- `imported`：新图片和当前模型向量已写入；
- `duplicate`：图片和当前模型向量已存在，可能补充了元数据；
- `embedding_added`：图片已存在，本次补充了当前模型向量。

成功响应使用 HTTP 200，避免前端为三种幂等结果维护不同分支。坏图片、超限图片或非法价格返回 400；数据库不可用返回 503。响应不得暴露数据库连接串、密码、模型内部异常或本地绝对路径。

### 5.2 `GET /api/library`

沿用现有端点，稳定按图片 ID 升序返回：

- 图片 ID、原始文件名、图片 URL、MIME、宽高；
- 已有编码器身份列表；
- 九个可空元数据字段。

前端以该接口为图库计数和图库列表的唯一数据源。

### 5.3 `POST /api/search`

沿用现有图片上传与 `top_k` 参数约束。每个结果除名次、图片 ID、文件名、URL 和相似度外，还返回九个可空元数据字段。

查询图片只在内存中处理，不写入文件或数据库。精确相同文件仍从结果中排除。无当前模型向量时返回空 `results` 和中文 `message`。

## 6. 服务与仓库边界

新增不可变的元数据值对象，用于 API、服务和仓库之间传递已经规范化的数据。职责划分如下：

- API：解析 multipart、限制上传大小、把空白文本规范化为 `None`、把业务异常转换为 HTTP 状态；
- `LibraryService`：协调图片校验、文件保存、编码、元数据更新、事务提交与失败清理；
- `ImageRepository`：查询图片、更新元数据、写入向量和执行检索，不自行提交事务；
- `image_assets`：验证图片内容并按 SHA-256 安全落盘，不处理业务元数据。

CLI 导入保持原有行为：未提供元数据时所有新增字段为 `NULL`。HTTP 和 CLI 共用相同的服务层入库逻辑，避免两条路径产生不同的去重、事务或文件清理规则。

## 7. 前端结构与数据流

新增 `api-client.js`，用 UMD 方式同时支持浏览器和 Node 测试。它只负责：

- `listLibrary()`；
- `uploadLibraryImage(file, metadata)`；
- `searchSimilar(file, topK)`；
- 校验非 2xx 响应并提取安全、可展示的中文错误。

`app.js` 负责 DOM 交互：

### 页面初始化

1. 请求 `GET /api/library`；
2. 更新图库数量；
3. 用后端 `image_url` 和元数据渲染列表；
4. 后端不可用时展示错误和重试入口，不回退到 IndexedDB。

### 买家秀入库

1. 保留现有图片预览和九个选填字段；
2. 提交期间禁用按钮并显示“正在入库”；
3. 调用 `POST /api/library`；
4. 成功后清空表单、恢复预览并重新请求图库列表；
5. 失败时保留表单与预览，展示后端返回的安全错误。

### 客户图片检索

1. 选择图片后只生成本地预览，不再计算九宫格特征；
2. 点击匹配后调用 `POST /api/search?top_k=5`；
3. 使用后端相似度、图片 URL 和元数据渲染结果；
4. 无结果时展示后端说明；失败时展示可重试错误。

前端移除 IndexedDB、`makeFeature()`、本地排序、演示数据、载入演示按钮和清空本机数据按钮。反馈按钮仍只提供当前页面内的确认提示，不承诺持久化。

渲染来自文件名和元数据的内容时使用 `textContent` 和 DOM 节点，不将后端文本拼接进 `innerHTML`，避免已入库文本形成脚本注入。

## 8. 展示规则

图库项：

- 主标题优先显示商品名，否则显示原始文件名；
- SKU 缺失时显示“未填写”；
- 标签只展示实际存在的空间、风格、颜色和库存；
- 没有标签时显示“元数据未填写”。

检索结果：

- 显示后端给出的相似度百分比；
- 推荐理由固定为“OpenCLIP 图片向量相似”；
- 商品字段缺失时保持中性占位，不推断 SKU、价格、规格或库存；
- 建议话术只使用实际返回的商品名和 `selling_point`，其余内容保持通用场景参考表达。

## 9. 错误与状态处理

- 初始图库加载失败：顶部计数显示 `—`，图库区域显示“无法连接后端”，提供“重新加载”按钮；
- 入库失败：表单不重置，提交按钮恢复可用，表单内显示错误；
- 检索失败：保留查询图片，结果区隐藏或保留上一次成功结果，匹配提示显示错误；
- 重复提交：按钮在请求期间禁用，防止同一页面产生并发重复请求；
- 响应不是 JSON：前端展示统一的“服务响应异常，请稍后重试”；
- 模型首次加载较慢：按钮持续显示处理中，不设置会误判模型加载失败的前端短超时。

## 10. 测试策略

### Python 测试

- schema 增量升级可重复执行，已有图片记录保留；
- 九个元数据字段均可为空并可持久化；
- 非空字段可补充或覆盖，空白字段不清除既有值；
- 新图片上传可保存文件、向量和元数据；
- 重复上传不增加图片记录，并返回稳定状态；
- 图库和检索响应包含元数据；
- 图片超限、坏图片、非法价格和数据库异常返回安全错误；
- 查询图片不写入图库。

### JavaScript 测试

- API 客户端为图库上传构造正确的 `FormData`；
- 空选填字段不写入请求；
- 检索使用正确路径与 `top_k`；
- 非 2xx JSON 错误和非 JSON 错误转换为稳定中文消息；
- 展示辅助函数对缺失元数据保持中性表达。

### 集成验证

1. 运行 Node 内置测试；
2. 运行 `pytest tests -m "not model"`；
3. 启动 FastAPI，确认 `/`、静态资源和 `/health` 同源可访问；
4. 上传一张买家秀并确认图库立即刷新；
5. 上传一张客户图并确认结果图片、相似度和选填元数据正常显示；
6. 刷新浏览器，确认图库仍来自数据库并保持存在。

真实 OpenCLIP 冒烟测试仍由 `RUN_MODEL_TESTS=1` 显式启用，避免普通测试触发权重下载。
