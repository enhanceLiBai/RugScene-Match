# 商品主图与买家秀关联检索设计

> 状态：待实施  
> 日期：2026-09-07

## 1. 目标

管理员通过网页导入腾讯文档导出的 `产品参数&价格.xlsx`。系统从“地毯图片”工作表建立商品主图与买家秀沙发图的确定性关联。客服上传客户居家图后，系统检索相似买家秀，按商品 ID 去重，并同时展示命中的买家秀、对应商品主图、商品 ID 和相似度。

本期以功能闭环和稳定运行优先，只实现直接需要的导入、关联、检索和展示能力。

## 2. Excel 映射规则

只处理“地毯图片”工作表，并按同一行建立关联：

- F 列：商品 ID，作为推荐商品的业务标识。
- K 列：商品主图（白底图）。
- L、M、N 列：参与场景检索的买家秀沙发图。
- J 列及 O–Q 列本期不导入推荐链路。

每个非空的 K、L、M、N 图片都作为独立图片记录保存。K 列图片标记为 `product_main`，L–N 列图片标记为 `buyer_sofa`。同一行的这些图片分别关联同一个商品 ID。

缺少商品 ID 的行整体跳过。某个可选图片缺失或无法解析时，只跳过该图片并记录原因，不影响同一行其他有效图片。

## 3. 数据库设计

保留现有 `images` 与 `image_embeddings` 表，新增 `product_images` 业务关联表：

- `id`：内部主键。
- `product_id`：Excel F 列商品 ID，按文本保存。
- `image_id`：关联 `images.id`。
- `image_role`：`product_main` 或 `buyer_sofa`。
- `source_column`：`K`、`L`、`M` 或 `N`。
- `is_active`：该关联是否参与当前展示或检索。
- `created_at`：创建时间。

通过唯一约束避免同一商品、同一图片和同一角色被重复关联。现阶段不新建完整 `products` 表；以后确需保存价格、规格等商品属性时再增加。

另新增 `import_jobs` 技术任务表，只保存导入任务 ID、状态、进度计数、结果摘要、错误摘要和时间，不保存商品资料。它用于页面查询后台处理进度，并保证应用重启后任务结果仍可查看。

只为 `buyer_sofa` 图片生成向量。商品主图仅用于展示，不占用向量生成和检索资源。

## 4. 增量导入

管理员在网页选择 `.xlsx` 文件后，浏览器将文件上传到后端。后端采用流式写盘，将文件暂存到 `data/import_jobs/<job_id>/`，避免将约 1.28 GB 文件整体载入内存。该目录必须加入 Git 忽略。

上传完成后返回任务 ID，后台任务依次执行：

1. 读取工作表结构和图片锚点。
2. 按 F、K、L、M、N 列建立行级关系。
3. 以图片 SHA-256 复用现有图片文件和记录。
4. 写入或复用 `product_images` 关联。
5. 只为新增或缺少当前模型向量的买家秀生成向量。
6. 汇总商品数、主图数、买家秀数、复用数、跳过数和失败明细。

重复导入采用增量同步：

- 字节相同的图片直接复用，不重复保存或生成向量。
- 新买家秀新增到原商品 ID 下。
- K 列主图变化时，新主图成为该商品当前展示主图，旧主图关联停用但图片文件暂不删除。
- 新版 Excel 中缺少的历史买家秀不自动删除或停用。

任务完成或失败后删除临时 Excel。已入库图片、关联、向量和任务摘要继续保留。

## 5. 任务进度

导入任务保存以下状态：`uploading`、`parsing`、`extracting`、`embedding`、`completed`、`failed`。页面根据任务 ID 查询进度，展示当前阶段、已处理数量和最终摘要。

单图失败不终止整份表格；无法打开工作簿、找不到目标工作表或数据库事务失败时，任务标记为失败并返回可读错误，不暴露内部路径或数据库信息。

首期在应用进程内执行后台任务，不引入消息队列或分布式任务系统。当前内部使用规模不需要额外基础设施。

## 6. 检索与商品去重

客户居家图只在内存中校验和编码，不写入文件或数据库。检索只查询已启用的 `buyer_sofa` 关联及当前配置模型的向量。

为返回 5 个不同商品，仓库先召回较多买家秀候选（首期固定为 30 条），按相似度从高到低遍历，并按商品 ID 去重。每个商品只保留相似度最高的买家秀。若不足 5 个商品，则返回实际可用数量。

每条结果包含：

- 商品 ID；
- 匹配买家秀图片地址；
- 对应的当前商品主图地址；
- 相似度；
- 买家秀来源列。

没有有效商品主图的商品不进入可推荐结果，避免客服看到无法对应白底图的推荐。

## 7. API 与页面

新增管理员导入接口，包括文件上传、任务状态查询和任务结果查询。现有搜索接口扩展商品关联字段，同时保留现有模型身份信息。

前端必须复用现有 `index.html`、`app.js`、`styles.css` 及已有推荐卡片，不新建独立前端项目、不引入新的前端框架。管理员导入入口整合到现有“买家秀图库”页面，客服检索继续使用现有匹配页面和交互流程。

现有客服推荐卡片扩展为并排展示相似买家秀和对应商品主图，显示商品 ID、匹配度，并提供复制商品 ID 的操作。图片文件缺失时显示明确占位提示；单条图片展示失败不影响其他推荐。

管理员导入页面显示文件选择、上传进度、后台处理阶段、数量统计和失败摘要。本期不增加价格、库存、规格筛选，也不提供历史买家秀自动删除功能。

## 8. 最小验证范围

只运行能证明本次业务闭环的直接相关测试：

- 同一行 K 与 L–N 图片正确关联同一商品 ID。
- 图片按原始字节提取，重复图片通过哈希复用。
- 只有买家秀沙发图生成并参与向量检索。
- 多张命中按商品 ID 去重并保留最高相似度。
- API 返回买家秀、商品主图、商品 ID 和相似度。
- 客服页面能够完成一次上传客户图并查看推荐的主流程。

不主动执行完整回归、压力测试、探索性缺陷搜索或与当前功能无关的代码审查。

## 9. 验收标准

- 管理员可从网页导入指定 Excel，并看到可理解的任务进度和结果摘要。
- 同一商品 ID 下的 K 列主图与 L–N 列买家秀形成正确关联。
- 客户居家图不会持久化。
- 检索结果按商品 ID 去重，每个商品展示其最高相似买家秀及对应主图。
- 重复导入不会重复保存相同图片或重复生成相同模型向量。
- 单张坏图或缺图不会中断整份文件中其他有效数据的导入。
